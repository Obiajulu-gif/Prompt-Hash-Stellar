# Provenance Tracking System

**Issue #929: Provenance tracking for imported and derived records**

## Overview

The provenance tracking system provides comprehensive audit trails for all prompts in the PromptHash platform. It tracks the complete lifecycle of prompts from creation through updates, including:

- **Import sources**: Where prompts originated (API, file upload, blockchain, etc.)
- **Transformations**: All changes applied to prompts over time
- **Lineage**: Parent-child relationships and derivation chains
- **Actor metadata**: Who performed each action
- **Batch tracking**: Group related imports for audit purposes

## Architecture

### Data Model

The system uses two complementary models:

1. **ProvenanceRecord** (Issue #929): Comprehensive tracking of imports, updates, and transformations
2. **PromptRelation** (Issue #753): Lightweight fork/remix relationships

#### ProvenanceRecord Schema

```typescript
{
  promptId: string;           // Internal prompt ID
  onChainId?: string;         // On-chain prompt ID (if applicable)
  sourceType: ImportSourceType;
  sourceSystem: {
    name: string;
    version: string;
    identifier: string;
  };
  importBatch?: {
    batchId: string;
    totalItems: number;
    importedAt: Date;
    importedBy: string;
  };
  transformations: [{
    transformType: TransformType;
    timestamp: Date;
    actor: ActorMetadata;
    details: string;
    metadata?: Record<string, any>;
  }];
  actor: ActorMetadata;
  parentRecordId?: string;    // For derived prompts
  childRecordIds: string[];
  createdAt: Date;
  updatedAt: Date;
}
```

### Import Source Types

- `API_IMPORT`: Imported via REST API
- `MANUAL_ENTRY`: Created through UI forms
- `FILE_UPLOAD`: Uploaded from CSV/JSON files
- `EXTERNAL_SYSTEM`: Synced from external platforms
- `BULK_IMPORT`: Batch import operations
- `BLOCKCHAIN`: On-chain prompt creation
- `AI_GENERATION`: Generated by AI systems
- `MIGRATION`: Migrated from legacy systems
- `SCRAPING`: Imported via web scraping

### Transform Types

- `TRANSLATION`: Language translation
- `FORMAT_CONVERSION`: Format/encoding changes
- `ENRICHMENT`: Metadata additions
- `VALIDATION`: Verification operations
- `NORMALIZATION`: Data normalization
- `AGGREGATION`: Data combination
- `FORK`: Forked from another prompt
- `REMIX`: Remixed/modified version
- `VERSION_UPDATE`: Version increments

## Integration Guide

### Automatic Tracking (Recommended)

The system provides middleware for automatic provenance tracking:

```typescript
import { 
  provenanceUpdateMiddleware, 
  capturePromptVersion 
} from "../middleware/provenanceMiddleware";

// In your update route
router.put("/prompts/:id", async (req, res) => {
  // Capture version before update
  await capturePromptVersion(req, req.params.id);
  
  // Apply middleware
  provenanceUpdateMiddleware(req, res, () => {});
  
  // Perform update
  const updated = await Prompt.findByIdAndUpdate(req.params.id, req.body, { new: true });
  
  // Provenance tracked automatically in background
  res.json({ prompt: updated });
});
```

### Manual Tracking

For more control, use service methods directly:

```typescript
import { trackPromptUpdate } from "../services/provenanceService";

const previous = await Prompt.findById(promptId).lean();
const updated = await Prompt.findByIdAndUpdate(promptId, updates);

await trackPromptUpdate({
  promptId,
  updateType: "CONTENT_ENHANCEMENT",
  updateDetails: "User updated content",
  actor: {
    userId: req.user.id,
    walletAddress: req.user.walletAddress,
    ipAddress: req.ip,
    timestamp: new Date(),
  },
  changedFields: ["content", "title"],
  previousVersion: previous,
});
```

## Performance Considerations

1. **Async Tracking**: Provenance tracking runs asynchronously to avoid blocking responses
2. **Batch Operations**: Use bulk import for large datasets
3. **Indexed Queries**: All common query patterns are indexed
4. **Denormalized Data**: Prompt model includes provenance references for quick lookups
5. **Background Processing**: Middleware doesn't wait for provenance completion

## Security & Privacy

- **Admin-only Statistics**: Import statistics require `provenance:read` scope
- **Wallet Sessions**: Derived tracking requires authenticated wallet sessions
- **Audit Trail**: All provenance operations are logged in the audit system
- **Actor Tracking**: Complete actor metadata captured for accountability

## Migration from Legacy Systems

For migrating existing prompts without provenance:

```typescript
import { createProvenanceRecord } from "../services/provenanceService";

// Create provenance for existing prompts
for (const prompt of existingPrompts) {
  await createProvenanceRecord({
    promptId: prompt._id,
    onChainId: prompt.onChainId,
    sourceType: "MIGRATION",
    sourceSystem: {
      name: "Legacy System",
      version: "1.0",
      identifier: `legacy_${prompt._id}`,
    },
    actor: {
      userId: "system",
      timestamp: prompt.createdAt,
    },
  });
}
```

## Troubleshooting

### Issue: Provenance not being tracked

**Solution**: Ensure middleware is integrated and `capturePromptVersion` is called before updates.

### Issue: Missing actor information

**Solution**: Verify authentication middleware runs before provenance middleware.

### Issue: Slow queries

**Solution**: Check indexes are created and queries use indexed fields.

### Issue: Batch import failures

**Solution**: Review batch status endpoint for detailed error messages per item.
